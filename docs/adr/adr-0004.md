# ADR: Progress Visualization Model

## Status
Proposed

## Context

The application needs to provide users with meaningful ways to visualize training progress. This is challenging because progress can be interpreted at multiple levels:

1. **Movement level** — e.g., how a specific exercise such as Back Squat has progressed over time.
2. **Workout level** — how repeated instances of a workout session (e.g., "Upper A") have evolved.
3. **Overall training trends** — broad summaries of activity, volume, or consistency.

The current UI shows a **Progress Overview** card listing recent movements. However, there is no clear interaction model for entering charting or selecting what to visualize.

Several UX questions arise:

- Where should users access charts from?
- How should users choose movements to chart?
- Should multiple movements be viewable together?
- How should repeated workouts be compared?

A single “chart mode” would introduce ambiguity because the user may want to chart different entities (movement vs workout).

Therefore a structured model is required that clearly separates these different visualization contexts.

---

## Decision

Progress visualization will be organized around **three distinct analysis modes**:

1. **Movement Progress**
2. **Workout Comparison**
3. **Progress Explorer (optional advanced entry point)**

Each mode has a clear UI entry point and purpose.

### 1. Movement Progress (Primary Visualization)

Movement progress is the primary visualization feature.

Users access it by tapping on a movement anywhere it appears in the UI.

Examples of entry points:

- Movement rows in **Progress Overview**
- Movement rows in **Workout Detail**
- Search within the **Progress Explorer**

Opening a movement shows a dedicated **Movement Progress screen**.

This screen displays:

- A chart of the selected movement over time
- Metric selector (e.g., best set, volume, estimated 1RM)
- Timeframe selector (e.g., 1M, 3M, 6M, 1Y, All)
- Optional comparison with other movements
- Historical logs of that movement

The default state always shows **one movement only**, ensuring clarity.

---

### 2. Multi-Movement Comparison

Users may compare multiple movements intentionally.

Multi-movement charts are enabled via a **Compare** action within the Movement Progress screen.

Example workflow:

1. User opens **Back Squat Progress**
2. User taps **Compare**
3. Movement picker opens
4. User selects additional movements

Suggested movements may include:

- Similar variations (e.g., Paused Squat, Front Squat)
- Recently performed movements
- Searchable list of all movements

Multi-movement charts are not shown by default to avoid visual complexity.

---

### 3. Workout Comparison

Workout comparison analyzes **entire workout sessions**, not individual movements.

This feature compares sessions belonging to the same **workout template**.

Example templates:

- Upper A
- Lower A
- Push
- Pull
