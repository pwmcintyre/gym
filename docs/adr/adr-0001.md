# ADR-001: Movement Identity, Variants, and Workout Prescriptions

**Status:** Accepted
**Date:** 2026-03-12

---

# Context

The application must track and compare strength training exercises entered manually or extracted from photos of workout programs.

A key design challenge is **how to determine whether two exercises represent the same activity**, particularly when exercises differ in:

* set counts
* rep targets
* modifiers (e.g. pauses or tempo)

Example inputs:

```
1x back squat
4x back squat
4x back squat with 3 second pause
```

These entries represent the **same base movement** but may differ in **prescription** or **modifiers**.

If the system treats each of these as completely separate exercises, it will fragment historical data and make comparisons (e.g. progress tracking) difficult.

Therefore we must establish a clear model for grouping and comparing exercises.

---

# Decision

We will separate exercise data into **three distinct conceptual layers**:

1. **Movement Identity**
2. **Modifiers (Variants)**
3. **Workout Prescription**

## 1. Movement Identity

Movement identity represents the **canonical exercise** independent of programming details.

Examples:

```
Back Squat
Bench Press
Deadlift
Pull-up
```

Movement identity is used as the **primary grouping key** for analytics and history.

Example:

```
1x back squat
4x back squat
```

Both resolve to the same movement identity:

```
movement = back_squat
```

---

## 2. Modifiers (Variants)

Modifiers represent **variations applied to a movement**.

Examples include:

* pauses
* tempo
* equipment
* stance changes

Example input:

```
4x back squat with 3 second pause
```

This resolves to:

```
movement = back_squat
modifier = pause
pause_seconds = 3
```

Modifiers produce **variants** of a movement.

Examples:

```
Back Squat
 ├ Pause Squat
 ├ Tempo Squat
 ├ High Bar Squat
 └ Pin Squat
```

Variants are considered **comparable but not identical** to the base movement.

---

## 3. Workout Prescription

Workout prescription describes **how the movement is programmed**.

Prescription includes:

* sets
* reps
* weight
* RPE
* rest time

Examples:

```
1x back squat
4x back squat
5x5 back squat
3x8 back squat
```

These are considered **the same movement** with different programming.

Prescription **does not affect movement identity**.

---

# Data Model

The system will use a normalized data model separating movements, modifiers, and sets.

Example TypeScript-style model:

```
Movement {
  id
  canonical_name
  aliases[]
  equipment
  primary_muscles[]
}

ExerciseInstance {
  movement_id
  modifiers[]
}

Set {
  reps
  weight
  modifier
}
```

Example stored exercise:

```
movement: Back Squat

exercise instance:
modifier: pause=3s

sets:
5 @ 100kg
5 @ 100kg
5 @ 100kg
5 @ 100kg
```

---

# Comparison Rules

Exercises are compared using the following hierarchy.

## Identical

```
same movement
same modifiers
```

Example:

```
Back Squat
Back Squat
```

## Variant

```
same movement
different modifiers
```

Example:

```
Back Squat
Pause Back Squat
```

These are comparable but tracked separately.

## Different Movement

```
different movement identity
```

Example:

```
Back Squat
Front Squat
```

These are not directly comparable.

---

# Grouping Rules

For historical tracking and analytics:

```
group by movement
subgroup by modifiers
ignore prescription
```

Example grouping:

```
Back Squat history

1x180kg
4x5 120kg
3x8 100kg
```

---

# Handling AI Program Parsing

When workout programs are parsed from images, the system will normalize entries into structured data.

Example detected text:

```
4x Back Squat
3s Pause
```

Normalized representation:

```json
{
 "movement": "back squat",
 "sets": 4,
 "modifier": {
   "type": "pause",
   "seconds": 3
 }
}
```

The system then resolves:

```
movement_id = BACK_SQUAT
modifier = pause
```

---

# Consequences

## Benefits

* Stable movement identity across different programming schemes
* Reliable exercise comparison and analytics
* Clean separation of movement and programming
* Simplifies AI normalization of parsed workout programs
* Allows future expansion of modifiers without schema changes

## Tradeoffs

* Requires a movement normalization layer
* Requires structured parsing of modifiers
* Some edge cases (tempo, equipment, stance) may require multiple modifiers

---

# Future Considerations

Future versions may introduce:

* movement taxonomy (movement families)
* automatic alias detection from AI parsing
* modifier normalization (tempo, stance, equipment)
* estimated 1RM comparisons across variants

Example movement taxonomy:

```
Squat
 ├ Back Squat
 ├ Front Squat
 └ Overhead Squat
```

This taxonomy is not required for the initial milestone.

---

# Summary

Exercises will be modeled using three layers:

```
Movement Identity
+ Modifiers
+ Workout Prescription
```

This structure allows the system to treat the following entries as related:

```
1x back squat
4x back squat
4x back squat with 3s pause
```
