## Codebase Patterns
- Room JVM unit tests (Robolectric): add `testImplementation("org.robolectric:robolectric:4.11.1")`, `androidx.test:core:1.5.0`, `kotlinx-coroutines-test`; set `@Config(sdk = [34])` to avoid compileSdk=35 warnings; enable `testOptions { unitTests.isIncludeAndroidResources = true }` in the Android block
- Use `Room.inMemoryDatabaseBuilder(...).allowMainThreadQueries()` for DAO tests in `src/test/`; collect flows with `.first()` inside `runTest {}`
- `GymAppRoot.kt` is the single root composable wrapping NavHost + Scaffold — global UI overlays (chat, notifications) belong here, outside NavHost
- `ModalBottomSheet` with `skipPartiallyExpanded = true` used for overlay sheet — placed after Scaffold in composition, not inside it
- Use `Icons.AutoMirrored.Filled.*` for Chat and Send icons (Filled variants deprecated in recent Material Icons)
- Feature overlays that should persist across navigation live in `app/` module, not in feature modules
- `ChatViewModel` lives in `app/` module (not a feature module) because it drives a global overlay
- `hiltViewModel()` called in `GymAppRoot` scope — ViewModel survives navigation because it's at the root composable level
- `LazyColumn` with `reverseLayout = true` + `items(messages.reversed())` pattern for chat lists — newest message at bottom; loading indicator inserted as first `item {}` block in reversed order
- `mutableStateListOf<T>` for ViewModel-owned lists that drive Compose recomposition without StateFlow overhead
- For assistant prompt payloads in the `app/` module, lightweight manual JSON string builders are simpler than adding serialization plugin support just for local prompt structs
- For small settings subflows, an internal screen-state switch inside the feature screen is cheaper than introducing another top-level nav route
